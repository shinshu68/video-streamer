# video-streamer 開発方針

## 目的・背景

Windows PC に接続した外付けHDDに保存している動画 (主に mp4) を、同じ LAN 内の Android 端末からストリーミング再生したい。ファイルをコピーせずに、アプリから一覧を見て選び、すぐ再生・シークできる状態を目指す。

SMB 共有を Android から直接読む方法や既製のメディアサーバー (Jellyfin など) を使う方法もあるが、Android 側の実装の簡単さと機能を自分で作り込める自由度を優先し、Windows 側に小さな HTTP サーバーを自作する構成にした。

## スコープ

### やること

- 公開フォルダ配下をフォルダ単位でたどって動画を選ぶ一覧表示
- 動画のストリーミング再生とシーク
- 一覧でのサムネイル表示

### やらないこと

- LAN の外 (インターネット経由) からのアクセス
- サーバー側での変換 (トランスコード)。mp4 をそのまま配信する
- iOS 版 (Flutter のため後から対応する余地は残す)
- 視聴済みの動画に印を付ける表示と、その情報の保存

### 後回しにすること

- 続きから再生 (途中まで見た位置の記録)

## 技術選定

| 対象 | 選んだ技術 | 理由 |
| --- | --- | --- |
| リポジトリ構成 | モノレポ | API を変えるときにサーバーとアプリを1つのブランチで直せ、Claude が両方の文脈を持って作業できるため |
| サーバー | Go | `http.ServeContent` が Range リクエストを自動で処理する。WSL から Windows 用の単一 exe をクロスビルドでき、Windows 側に実行環境を用意せずに済むため |
| アプリ | Flutter | 既存の Flutter プロジェクト (wakeup-alarm) の環境やビルド手順を流用できる。`video_player` パッケージは Android では内部で ExoPlayer を使い、mp4 の HTTP ストリーミングとシークに対応しているため。将来 iOS 版を作る余地も残る |
| サムネイル生成 | ffmpeg | 動画から任意の位置のフレームを画像として切り出せるため |

## 設計方針

詳細は [architecture.md](architecture.md) を参照する。要点は次のとおり。

- サーバーは Windows 上で動かす。WSL 内で動かすと `/mnt/` 経由のHDDの読み込みが遅く、LAN から WSL へ接続するためのネットワーク設定も必要になるため
- 公開フォルダは設定ファイルで指定する。外付けHDDのドライブ文字が変わる可能性があるため
- API の変更は docs/api.md → server/ → android/ の順に行う

## 進め方

1. サーバー: 一覧 API と動画配信を作り、curl と PC の VLC (配信 URL を開く) で再生とシークを確認する
2. アプリ: 一覧画面と再生画面を作り、Pixel 6a で再生とシークを確認する
3. サムネイル表示 (サーバーでの生成と、アプリの一覧への表示)
4. Windows 上での常駐 (deployment.md の手順を確定させる)

サーバーを先に完成させ、アプリの不具合とサーバーの不具合を切り分けやすくする。
