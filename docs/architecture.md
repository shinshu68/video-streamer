# アーキテクチャ

## 全体構成

```
[Android 端末 (Flutter アプリ)]
        │  HTTP (LAN 内)
        ▼
[Windows PC (Go サーバー)]
        │  ファイル読み込み
        ▼
[外付けHDD の公開フォルダ]
```

## データの流れ

1. アプリが一覧 API で公開フォルダの中身 (フォルダと mp4) を取得し、一覧画面に表示する
2. 一覧の各動画について、サムネイル API から画像を取得して表示する
3. 動画を選ぶと、配信 URL (`/media/...`) を `video_player` に渡して再生する
4. シーク時は、プレイヤーが Range リクエストで必要な位置のデータだけを取得する
5. 視聴済みの印を付ける (保存先は未定。plan.md の未決事項を参照)

各 API の詳細は [api.md](api.md) を参照する。

## server/ の役割

| 役割 | 内容 |
| --- | --- |
| 設定の読み込み | 公開フォルダのパス、ポート番号などを設定ファイルから読む |
| パスの検証 | リクエストのパスを正規化し、公開フォルダの外を指すものを拒否する |
| 一覧 | 指定フォルダ配下のフォルダと mp4 を返す |
| 配信 | `http.ServeContent` で Range 対応の配信を行う |
| サムネイル | 初めて要求されたときに ffmpeg で先頭から10秒の位置のフレームを切り出し、JPEG で返す。生成した画像は exe の隣の cache\thumbnails\ に保存し、2回目以降はそこから返す。HDD への負荷を抑えるため、同時に動かす ffmpeg は2つまでにする |

事前の一括生成は、本数が多いと起動後しばらく HDD に負荷がかかり、動画を追加したときの作り直しの仕組みも要るため採用していない。

## android/ の役割

| 画面・機能 | 内容 |
| --- | --- |
| 一覧画面 | フォルダをたどって動画を選ぶ。サムネイルと視聴済みの印を表示する |
| 再生画面 | `video_player` で配信 URL を再生する。シークに対応する |
| サーバーの指定 | 設定画面でサーバーのアドレス (`192.168.0.10:8765` など) を手入力し、端末に保存する。受け付けるのはプライベート IP (10/8・172.16/12・192.168/16) だけ |

mDNS などでの自動検出は、サーバー側に広告の仕組みとファイアウォールの設定が別途必要になるため採用していない。アドレスの入力をし直さずに済むよう、PC の IP はルーターの DHCP 予約で固定する (deployment.md を参照)。

平文の HTTP は、Android の network_security_config でアプリ全体に許可する。network_security_config では IP アドレスの範囲や実行時に決まるアドレスを指定できないため、LAN 内に限る検証はアプリ側で行う。

## 設計上の注意点

- mp4 の目次情報 (moov) がファイル末尾にある場合も、Range 対応によりプレイヤーが末尾を先に読みに行くため再生できる。ただし再生開始が遅れることがある
- 外付けHDDがスリープしていると、最初の一覧取得や再生開始が遅れることがある。アプリ側のタイムアウトはこれを考慮した長さにする
