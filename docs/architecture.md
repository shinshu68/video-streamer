# アーキテクチャ

## 全体構成

```
[Android 端末 (Flutter アプリ)]
        │  HTTP (LAN 内)
        ▼
[Windows PC (Go サーバー)]
        │  ファイル読み込み
        ▼
[外付けHDD の公開フォルダ]
```

## データの流れ

1. アプリが一覧 API で公開フォルダの中身 (フォルダと mp4) を取得し、一覧画面に表示する
2. 一覧の各動画について、サムネイル API から画像を取得して表示する
3. 動画を選ぶと、配信 URL (`/media/...`) を `video_player` に渡して再生する
4. シーク時は、プレイヤーが Range リクエストで必要な位置のデータだけを取得する

各 API の詳細は [api.md](api.md) を参照する。

## server/ の役割

| 役割 | 内容 |
| --- | --- |
| 設定の読み込み | 公開フォルダのパス、ポート番号などを設定ファイルから読む |
| パスの検証 | リクエストのパスを正規化し、公開フォルダの外を指すものを拒否する |
| 一覧 | 指定フォルダ配下のフォルダと mp4 を返す |
| 識別子 | 動画のサイズと、先頭・末尾それぞれ 1MiB の SHA-256 から識別子を作り、一覧で返す。名前・フォルダ・更新日時が変わっても、中身が同じなら同じ識別子になる。識別子とパスの索引をキャッシュのフォルダに保存し、識別子から今のパスを引けるようにする。索引は一覧を返すときにそのフォルダの分だけ作り、サイズか更新日時が変わった動画だけを読み直す。索引にない識別子を要求されたときだけ、公開フォルダ全体を走査し直す |
| 配信 | `http.ServeContent` で Range 対応の配信を行う |
| サムネイル | 初めて要求されたときに ffprobe で動画の長さを調べ、ffmpeg で長さの 10% の位置のフレームを切り出し、JPEG で返す。長さに合わせて位置を決めるのは、冒頭の黒い画面やタイトルを、短い動画でも長い動画でも避けやすくするため。生成した画像は設定で指定したキャッシュのフォルダ (外付けHDD上) の thumbnails\ に保存し、2回目以降はそこから返す。HDD への負荷を抑えるため、同時に動かす ffmpeg は2つまでにする |

事前の一括生成は、本数が多いと起動後しばらく HDD に負荷がかかり、動画を追加したときの作り直しの仕組みも要るため採用していない。

## android/ の役割

| 画面・機能 | 内容 |
| --- | --- |
| 一覧画面 | フォルダをたどって動画を選ぶ。サムネイルを表示する (横型の動画は横長の枠、縦型の動画は縦長の枠で出し、縦型の行はその分高くなる)。お気に入りの画面を開ける |
| 再生画面 | `video_player` で配信 URL を再生する。シークに対応する。縦向きのときは、縦スクロールで前後の動画に切り替える (先頭と末尾の先には進まない)。端末を横向きにすると全画面になり、ステータスバーとナビゲーションバーを隠す。ハートのボタンでお気に入りを付け外しする (縦向きは動画の右下に重ね、横向きはタップで出す操作の中のシークバーの上に置く)。ハートの隣のボタンでピクチャーインピクチャーに入る |
| お気に入りの画面 | お気に入りにした動画を、新しく付けたものから順に表示し、選ぶと再生する。再生画面での前後の切り替えは、この画面の並び順に従う。サーバーで見つからない動画は末尾に「見つかりません」と薄く出し、ボタンで外せる |
| サーバーの指定 | 設定画面でサーバーのアドレス (`192.168.0.10:8765` など) を手入力し、端末に保存する。受け付けるのはプライベート IP (10/8・172.16/12・192.168/16) だけ |

サムネイルの枠の向きは、取得した画像の縦横比で決める。一覧 API で動画の縦横を返す方法は、一覧を返すたびに全ての動画を ffprobe で調べることになり、外付けHDDへの負荷が大きいため採用していない。全ての行を同じ大きさの正方形の枠にする方法は、横型の行まで高くなり、1画面に出せる件数が減るため採用していない。

mDNS などでの自動検出は、サーバー側に広告の仕組みとファイアウォールの設定が別途必要になるため採用していない。アドレスの入力をし直さずに済むよう、PC の IP はルーターの DHCP 予約で固定する (deployment.md を参照)。

再生画面で切り替える前後の動画は、開いた画面 (フォルダの一覧かお気に入りの画面) の並び順で決める。サブフォルダもたどって切り替える方法は、フォルダごとに一覧 API を呼ぶ必要があり複雑になるため採用していない。

切り替えた先の動画は、スクロールが止まってから読み込みを始める。前後の動画を先に読み込んでおく方法は、見ない動画の分まで外付けHDDから読むことになるため採用していない。横向きの全画面では切り替えない。画面の上下の端からのスワイプが、隠したステータスバーとナビゲーションバーを出す操作と重なるため。

お気に入りは、動画の識別子と名前の一覧として端末内 (shared_preferences) に保存する。名前も持つのは、サーバーで見つからなくなった動画がどれかを画面に出すため。サーバーに保存すれば複数の端末で共有できるが、API とサーバーの保存の仕組みが要るため採用していない。相対パスで保存しないのは、動画を NAS に移してフォルダ構造を見直したときに、お気に入りから外れないようにするため。移したあとに見つからなくなったパスを、ファイル名とサイズで探し直す方法は、名前を変えると外れるため採用していない。

索引を起動時に公開フォルダ全体から作る方法は、初回の起動で全ての動画を読み、HDD への負荷がしばらく続くため採用していない。お気に入りは一覧から付けるので、開いたフォルダの分の索引で普段は足りる。

ピクチャーインピクチャーは、`video_player` が対応していないため、Android のネイティブ側 (MainActivity) で実装し、Flutter とは MethodChannel でやり取りする。アプリを離れたときに自動では入らず、再生画面のボタンを押したときだけ入る。小窓には動画だけを出し、前の動画・再生と一時停止・次の動画のボタンを `RemoteAction` で足す。小窓を閉じると再生をやめ、アプリのタスクも終わらせる。

平文の HTTP は、Android の network_security_config でアプリ全体に許可する。network_security_config では IP アドレスの範囲や実行時に決まるアドレスを指定できないため、LAN 内に限る検証はアプリ側で行う。

## 設計上の注意点

- mp4 の目次情報 (moov) がファイル末尾にある場合も、Range 対応によりプレイヤーが末尾を先に読みに行くため再生できる。ただし再生開始が遅れることがある
- 外付けHDDがスリープしていると、最初の一覧取得や再生開始が遅れることがある。アプリ側のタイムアウトはこれを考慮した長さにする
