# API 仕様

サーバー (server/) とアプリ (android/) の間の API 仕様。両者の唯一の正とし、API を変更するときはこのファイルを先に更新する。

> 状態: 一覧の取得、動画の配信、サムネイルの取得、識別子からの動画の取得は確定。

## 共通

- プロトコル: HTTP
- ベース URL: `http://<サーバーのアドレス>:<ポート>` (ポートは設定ファイルで指定する。例の値は `8765`)
- 認証: なし (LAN 内限定のため。plan.md の未決事項を参照)
- 文字コード: UTF-8
- `path` は公開フォルダのルートからの相対パスで、区切り文字は `/` に統一する (Windows の `\` はサーバー側で変換する)
- 動画として扱うのは拡張子が `.mp4` のファイル (大文字小文字は区別しない)
- 次のファイル・フォルダは扱わない (一覧に含めず、指定されたら `404 Not Found` を返す)
  - 名前が `.` で始まるもの
  - Windows の隠し属性またはシステム属性が付いたもの (ドライブのルートを公開したときの `$RECYCLE.BIN` や `System Volume Information` など)
  - シンボリックリンクとジャンクション
  - サーバーのキャッシュのフォルダとその中 (公開フォルダの中に置いた場合)
- 公開フォルダの外を指す `path` は `403 Forbidden` を返す
- 存在しない `path` は `404 Not Found` を返す

### エラーレスポンス

`/api/` 配下のエラーは、ステータスコードに加えて次の JSON を返す。`error` は人が読むためのメッセージで、アプリはステータスコードで判定する。

```json
{ "error": "not found" }
```

## エンドポイント

### 一覧の取得

```
GET /api/list?path=<フォルダの相対パス>
```

`path` を省略すると公開フォルダのルートを返す。動画ファイルとフォルダだけを返し、それ以外のファイルは含めない。`path` がフォルダでない場合は `404 Not Found` を返す。

`entries` はフォルダを先に、それぞれの中は `name` の昇順に並べる。`type` が `video` のときだけ `id` (動画の識別子)、`size` (バイト数)、`modified` (更新日時、RFC 3339) を持つ。ルートを返すときの `path` は空文字列。

`id` は動画のサイズと、先頭・末尾それぞれ 1MiB の SHA-256 を16進数で表した64文字。名前・フォルダ・更新日時が変わっても、中身が同じなら同じ値になる。読み込みに失敗した動画と、計算が応答に間に合わなかった動画には `id` を付けない。

初めて一覧を返す動画と、サイズか更新日時が変わった動画は、`id` を求めるためにファイルを読むので、応答が遅くなることがある。サーバーは `id` の計算を最大 15 秒待って応答し、間に合わなかった動画の計算は応答のあとも続ける。計算が終わった動画は、次の一覧の取得で `id` を返す。

レスポンス例:

```json
{
  "path": "フォルダA",
  "entries": [
    { "type": "dir", "name": "サブフォルダB", "path": "フォルダA/サブフォルダB" },
    { "type": "video", "id": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08", "name": "動画C.mp4", "path": "フォルダA/動画C.mp4", "size": 123456789, "modified": "2026-10-25T12:00:00+09:00" }
  ]
}
```

### 識別子からの動画の取得

```
POST /api/videos
```

リクエストの本文で渡した識別子の動画を、今のパスとともに返す。

```json
{ "ids": ["9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"] }
```

`videos` は `ids` の順に、一覧の `entries` の動画と同じ形で返す。見つからない識別子は含めない。同じ中身の動画が複数あるときは、そのうちの1つを返す。本文が JSON として不正な場合は `400 Bad Request` を返す。

レスポンス例:

```json
{
  "videos": [
    { "type": "video", "id": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08", "name": "動画C.mp4", "path": "フォルダA/動画C.mp4", "size": 123456789, "modified": "2026-10-25T12:00:00+09:00" }
  ]
}
```

索引にない識別子があるときは公開フォルダ全体を走査し直すため、応答に時間がかかることがある。動画を移した直後は、クライアントがタイムアウトしても走査は続き、次の要求で結果を返せる。走査しても見つからなかった識別子は、10 分間は走査し直さない。読めないサブフォルダや動画があって走査が不完全だったときは、1 分で走査し直す。公開フォルダを読めないときは `500 Internal Server Error` を返す。

### 動画の配信

```
GET /media/<動画の相対パス>
```

パスの各要素は URL エンコードする (例: `/media/%E3%83%95%E3%82%A9%E3%83%AB%E3%83%80A/%E5%8B%95%E7%94%BBC.mp4`)。Range リクエストに対応し、`206 Partial Content` で部分的に返す。`Content-Type` は `video/mp4`。動画でないファイルを指す場合は `404 Not Found` を返す。エラー時の本文はテキストで、JSON ではない。

### サムネイルの取得

```
GET /api/thumbnail?path=<動画の相対パス>
```

動画の長さの 10% の位置のフレームを、幅 320px (高さは縦横比を保つ) の JPEG で返す。長さが分からない動画は先頭のフレームを使う。`Content-Type` は `image/jpeg`。

- 初めて要求されたときにサーバーで生成するため、応答に数秒かかることがある。2回目以降はサーバーのキャッシュから返す
- 動画のサイズか更新日時が変わったとき、またはサーバーでの作り方 (フレームの位置など) を変えたときは、次の要求で作り直す
- `path` が動画でない場合は `404 Not Found` を返す
- 生成に失敗した場合 (ffmpeg がない、動画が壊れているなど) は `500 Internal Server Error` を返す。アプリは代わりのアイコンを表示する。同じ動画の生成は 10 分間は試し直さず、同じエラーを返す
