# API 仕様

サーバー (server/) とアプリ (android/) の間の API 仕様。両者の唯一の正とし、API を変更するときはこのファイルを先に更新する。

> 状態: 一覧の取得と動画の配信は確定。サムネイルと視聴済みは案。

## 共通

- プロトコル: HTTP
- ベース URL: `http://<サーバーのアドレス>:<ポート>` (ポートは設定ファイルで指定する。例の値は `8765`)
- 認証: なし (LAN 内限定のため。plan.md の未決事項を参照)
- 文字コード: UTF-8
- `path` は公開フォルダのルートからの相対パスで、区切り文字は `/` に統一する (Windows の `\` はサーバー側で変換する)
- 動画として扱うのは拡張子が `.mp4` のファイル (大文字小文字は区別しない)
- 名前が `.` で始まるファイル・フォルダと、シンボリックリンクは扱わない (一覧に含めず、指定されたら `404 Not Found` を返す)
- 公開フォルダの外を指す `path` は `403 Forbidden` を返す
- 存在しない `path` は `404 Not Found` を返す

### エラーレスポンス

`/api/` 配下のエラーは、ステータスコードに加えて次の JSON を返す。`error` は人が読むためのメッセージで、アプリはステータスコードで判定する。

```json
{ "error": "not found" }
```

## エンドポイント

### 一覧の取得

```
GET /api/list?path=<フォルダの相対パス>
```

`path` を省略すると公開フォルダのルートを返す。動画ファイルとフォルダだけを返し、それ以外のファイルは含めない。`path` がフォルダでない場合は `404 Not Found` を返す。

`entries` はフォルダを先に、それぞれの中は `name` の昇順に並べる。`type` が `video` のときだけ `size` (バイト数) と `modified` (更新日時、RFC 3339) を持つ。ルートを返すときの `path` は空文字列。

レスポンス例:

```json
{
  "path": "フォルダA",
  "entries": [
    { "type": "dir", "name": "サブフォルダB", "path": "フォルダA/サブフォルダB" },
    { "type": "video", "name": "動画C.mp4", "path": "フォルダA/動画C.mp4", "size": 123456789, "modified": "2026-10-25T12:00:00+09:00" }
  ]
}
```

### 動画の配信

```
GET /media/<動画の相対パス>
```

パスの各要素は URL エンコードする (例: `/media/%E3%83%95%E3%82%A9%E3%83%AB%E3%83%80A/%E5%8B%95%E7%94%BBC.mp4`)。Range リクエストに対応し、`206 Partial Content` で部分的に返す。`Content-Type` は `video/mp4`。動画でないファイルを指す場合は `404 Not Found` を返す。エラー時の本文はテキストで、JSON ではない。

### サムネイルの取得 (案)

```
GET /api/thumbnail?path=<動画の相対パス>
```

JPEG 画像を返す。生成タイミングとキャッシュは未定 (plan.md の未決事項を参照)。
